# DeepSeek Harness AI 产品经理工作台：简单版 Alpha 设计

**日期：** 2026-09-04

**状态：** 已于 2026-09-05 书面确认；先实施 §8.1 可交互 Demo

**目标版本：** DeepSeek Harness `0.1.0-rc.6`

**目标用户：** 个人 AI 产品经理

## 1. 第一版只证明一件事

> 一份访谈文字，能否经过 AI 辅助整理，变成一组有原文依据、由产品经理最终确认，并可进入 PRD 的需求。

核心流程固定为：

```text
访谈文字或文本文件
        ↓
AI 提取原文引用、痛点和候选需求
        ↓
AI 给出高 / 中 / 低优先级建议和理由
        ↓
产品经理修改并决定纳入 / 暂缓 / 不做
        ↓
只使用“已纳入”的需求生成 Markdown PRD
```

本设计替代此前复杂的 F0/H0/P0/P1 实施路线，成为简单版 Alpha 的当前执行依据。旧文档保留为研究记录，不再作为本版本的实施清单。

## 2. 完整用户流程

### 2.1 新建项目并放入材料

用户填写项目名称，然后选择一种输入方式：

- 直接粘贴访谈文字；
- 上传 `.txt` 或 `.md` 文件。

输入必须是 UTF-8 纯文本，原始文件最多 256 KiB，解码后最多 80,000 个 UTF-16 code units，去除首尾空白后不能为空，也不能包含 NUL 字符。格式、编码或大小不符合要求时，界面显示具体原因，不创建项目结果。

一个 Alpha 项目只包含一份已经确认的原始材料。开始分析后，如果用户要替换材料，需要新建项目。第一版不做材料更新和历史版本管理。

### 2.2 分析访谈

点击“分析访谈”前，界面明确提示：材料将被发送给 DeepSeek Harness 当前配置的模型提供方。用户必须主动确认后才能发送。

AI 生成两种需求卡片。所有卡片都包含痛点解释、候选需求、AI 判断理由和建议优先级：

- **有引用的需求**：包含一条或多条可回看的原文引用，可以由用户标记为纳入、暂缓或不做；
- **仅推断的需求**：不包含原文引用，必须显示“AI 推断，待确认”，只能标记为暂缓或不做。

“原文引用”必须逐字对应当前材料中的一个确定片段。引用无法在原文中定位时，这次分析结果无效，不能显示为成功。AI 的解释和推断必须与引用分开显示。仅推断的需求不能进入 Alpha PRD。

分析失败时显示失败原因，不得偷偷回退到预置示例结果。

### 2.3 人工判断

用户可以：

- 修改需求名称、描述和痛点解释；
- 将优先级设为高、中或低；
- 将处理结论设为纳入、暂缓或不做；
- 补充自己的判断理由。

第一版不提供专门的需求合并和永久删除功能。用户认为两个需求重复时，可以保留一个并把另一个标为“不做”。这样所有 AI 建议和人工决定都保留在当前项目中。

AI 只提出建议，最终结论始终由用户决定。已经人工修改的需求不得被后续操作静默覆盖。若用户选择重新分析，界面必须先说明这会替换尚未确认的 AI 草稿；存在人工修改时，第一版要求新建项目。

### 2.4 生成 PRD

系统只根据用户最终标记为“纳入”的需求生成 PRD。没有任何需求被纳入时，“生成 PRD”不可执行并说明原因。

第一版 PRD 包含：

1. 背景与问题；
2. 目标用户；
3. 用户痛点及访谈依据；
4. 本期目标；
5. 功能需求和优先级；
6. 非本期范围；
7. 成功指标；
8. 风险与待确认问题。

没有材料依据的用户数量、市场规模、上线时间、成功指标和技术方案显示“待产品经理补充”，不得自动编造。Alpha 界面不提供 PRD 正文编辑；用户导出 Markdown 后可以在自己的编辑器中继续补充。

用户可以预览 PRD，并导出 UTF-8、无 BOM 的 Markdown 文件。文件名为经过安全化处理的项目名称加 `-prd.md`；名称为空或无法安全化时使用 `pm-workbench-prd.md`。

导出的 PRD 必须包含项目 ID、材料 SHA-256、每个纳入需求的稳定 ID，以及对应原文引用的起止位置。重新打开导出文件后，这些追溯信息仍然存在。

## 3. 第一版界面

插件在 DeepSeek Harness 中提供一个“AI 产品经理工作台”入口。打开后先显示项目列表，用户可以新建、重新打开或删除项目。删除必须显示项目名称并二次确认；持久化删除失败时项目仍然保留。进入某个项目后使用连续的四步工作区：

1. **材料**：粘贴或上传访谈文字；
2. **需求**：查看原文引用、痛点和候选需求；
3. **优先级**：编辑高 / 中 / 低和纳入结论；
4. **PRD**：预览并导出 Markdown。

页面始终显示当前步骤和保存状态：

- `未保存`：本地状态有变化；
- `保存中`：Host 正在写入当前项目快照；
- `已保存`：最近一次快照已原子写入；
- `保存失败`：写入失败，界面保留当前未保存内容并允许重试，不得显示成功。

刷新页面或重新启动同一 Harness profile 后，当前项目的材料、分析结果、人工判断和 PRD 仍然存在。

## 4. AI 与人的分工

AI 负责：

- 将访谈文字整理为候选需求；
- 找出相关原文片段；
- 解释痛点；
- 给出优先级建议和理由；
- 根据确认后的需求起草 PRD。

产品经理负责：

- 判断 AI 的解释是否成立；
- 修改需求；
- 决定最终优先级；
- 决定纳入、暂缓或不做；
- 确认并导出 PRD。

## 5. 当前项目保存什么

Host 保存一个项目列表以及每个项目的当前快照。新建项目不会覆盖已有项目；用户可以从列表重新打开或经确认后删除项目。第一版最多保存 20 个项目，不提供归档或项目历史版本功能。达到上限时停止创建并提示用户删除不再需要的项目，不得自动淘汰旧项目。

每个项目快照至少包含：

- 项目 ID、名称和更新时间；
- 原始材料文本、文件名、字节数和 SHA-256；
- 最近一次模型运行的状态、时间、错误类别，以及 Harness 能够提供的模型/提供方标识；
- 每条原文引用在材料中的 UTF-16 半开区间 `[start, end)`、引用文本和引用 SHA-256；
- 每条需求的稳定 ID、AI 建议、人工修改标记、最终优先级、处理结论和人工理由；
- 最近生成的 PRD、生成时间、所使用的材料 SHA-256 和需求 ID 列表。

如果 Harness 没有返回模型或提供方名称，界面显示“由 Harness 管理，身份未返回”，不得猜测。

Client 只展示和编辑当前状态，不能把访谈材料或项目结果保存在 `localStorage`、`sessionStorage` 或 IndexedDB 中。生产存储必须位于当前 Harness profile 的插件数据范围。具体存储 API 在兼容性验证中从目标版本的实际接口确定；如果目标版本没有可用的受支持存储入口，Alpha 阻塞，不改用隐藏目录或浏览器存储绕过。

材料追溯使用一套固定规则：

- 粘贴内容按浏览器提交的原始 JavaScript 字符串保存，不修剪、不改换行、不做 Unicode normalization；
- 文件必须使用 fatal UTF-8 解码；允许并只移除文件开头的一个 UTF-8 BOM，其他字节解码失败即拒绝；
- 文件换行保持解码后的原样，不把 CRLF 改成 LF；
- 材料 SHA-256 是对最终持久化字符串重新编码得到的 UTF-8 字节计算；
- 引用位置是该持久化字符串上的 UTF-16 code-unit 半开区间 `[start, end)`；
- 引用文本必须严格等于 `material.slice(start, end)`，引用 SHA-256 对该引用文本的 UTF-8 字节计算。

界面、Host 快照、Markdown 导出和自动化测试使用同一套规则。

## 6. 模型调用与隐私边界

Alpha 只能使用目标 Harness 版本中实际验证过、能够返回结构化结果的受支持模型调用入口。不得抓取聊天消息、解析页面文本或依赖未公开的 DOM 来冒充模型接口。

兼容性验证必须先确认：

- 插件如何调用当前配置的模型；
- 能否获得结构化结果或可靠验证结果结构；
- 取消、超时和失败如何返回；
- 插件卸载后是否停止尚未完成的运行；
- Harness 是否返回模型或提供方标识。

如果这些条件在 `0.1.0-rc.6` 中不成立，本版本停止在明确标注的交互 Demo，不能称为“真实 AI Alpha”。

正式验收只使用新写的、无个人隐私和商业秘密的合成访谈材料。界面在模型调用前持续提示数据会发送给当前模型提供方；在提供方、留存与传输边界完成单独核验前，不宣称适合真实敏感访谈。

## 7. 最小实现结构

简单版包含四个独立模块：

- **材料模块**：验证并接收文字、TXT 和 Markdown；
- **分析模块**：调用模型并生成带原文引用的候选需求；
- **决策模块**：保存人工修改、优先级和纳入结论；
- **PRD 模块**：生成、预览和导出 Markdown。

模型调用和项目保存各自通过一个内部接口接入。第一版只实现目标 Harness 所需的一个生产适配器，不同时开发多个模型或存储后端。

示例数据只能用于界面开发和测试，并持续显示“演示数据，未连接真实模型”。

## 8. Demo 和 Alpha 分开验收

### 8.1 可交互 Demo

Demo 可以运行在独立的本地开发预览页，用来检查四步流程和视觉交互。它必须持续显示：

> 演示数据，未连接 DeepSeek Harness，未调用真实模型。

Demo 至少证明：材料输入、需求卡片编辑、优先级与纳入结论修改、PRD 预览，以及浏览器下载 Markdown 的交互可以工作。Demo 不证明插件安装、Harness 兼容、真实模型或 Host 持久化。

### 8.2 可安装 Alpha

Alpha 必须使用打包产物，在全新隔离的目标 Harness profile 中完成：安装、加载、入口挂载、四步流程、profile 重启后的状态恢复、Markdown 导出和卸载。分析必须调用真实受支持的 Harness 模型入口；任何模拟结果都不能满足 Alpha 验收。

## 9. 本版本明确不做

- 录音转写和说话人识别；
- Word、PDF、图片和视频解析；
- 材料更新、项目归档、项目历史版本和需求合并；
- 自动生成高保真原型；
- 自动开发 POC；
- 飞书、Notion、Jira、Figma 等外部集成；
- 多人实时协作；
- 自动市场调研和竞品分析；
- RICE、Kano 等复杂评分体系；
- 自动排期和研发工作量估算；
- 大量访谈的统计仪表盘；
- 企业级权限和审批系统。

## 10. 可复算验收标准

简单版 Alpha 只有同时满足以下条件才算完成：

1. 打包产物能在隔离的 DeepSeek Harness `0.1.0-rc.6` profile 中安装、打开和卸载；
2. 用户输入一份未预先用于演示的新合成访谈文字，能够完成分析到 PRD 的流程；
3. 每个“原文引用”的文本都严格等于所记录材料区间，无法定位的引用使分析失败；
4. 没有引用依据的内容只能标成“AI 推断，待确认”，并且不能被纳入 Alpha PRD；
5. 用户可以修改需求、优先级和纳入结论，人工修改不会被静默覆盖；
6. PRD 只包含最终确认纳入的需求，并保留项目、材料、需求和引用标识；
7. 新建项目不会覆盖旧项目；刷新页面和重启同一 profile 后，项目列表、各项目当前快照与 PRD 仍然存在；删除只有在确认和持久化成功后才从列表消失；
8. 导出的文件名符合规则，文件是 UTF-8、无 BOM，文件 SHA-256 与界面显示的导出结果一致；
9. 空文件、不支持的扩展名、非 UTF-8、NUL、超过限制、模型失败或保存失败都显示真实错误，并且不产生伪造成功结果；
10. 模型运行记录的成功或失败来自真实 Harness 调用；身份未返回时明确显示未知；
11. 演示数据、模拟模型和真实模型结果在界面与验收记录中清楚区分；
12. 安装验收使用固定合成样例，另用一份实现期间未见的合成样例检查引用定位、推断标记和人工决定保护。

自动化测试至少覆盖：伪造引用拒绝、推断标记、只导出已纳入需求、人工决定保护、输入校验、保存失败，以及导出字节稳定性。

## 11. 通过语句

第一次可用验收只接受下面这个结果：

> 在真实 DeepSeek Harness 中打开已安装插件，输入一段新的无敏感信息访谈文字，通过真实 Harness 模型得到有原文依据的需求，由产品经理修改优先级和纳入结论后，保存项目并导出一份可追溯的 Markdown PRD。
