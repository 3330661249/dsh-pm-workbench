# AI PM 工作台完整验证链路

用户于 2026-09-19 明确授权直接实现整条链路，采纳本轮工程取舍，无需逐项再次确认。

## 目标与范围
在已有 DeepSeek Harness rc.6 插件中跑通：TXT/MD/DOCX/粘贴正文 → AI 提炼 → 人工确认需求与优先级 → create-prd PRD → A 版验证中心 → 人工结论 → 研发交付。沿用黑白灰透明界面及宿主涟漪背景。

验证中心提供独立可选的 Demo、核心能力测试、受控模板 POC。Demo 是明确标识模拟数据的交互界面；能力测试与 POC 真实调用宿主当前模型。POC 以本工作台内可运行的标准输入/处理/输出模板交付，不执行生成的任意代码、不接第三方业务系统。公开发布与正式产品开发不在本次范围。

## 数据及状态
验证域独立存储，不迁移现有 schemaVersion=1 项目。每个任务绑定 projectId、确切 prdRevisionId/hash、baselineId 和选中需求；历史绑定不随当前 PRD 改变。任务状态：draft → confirmed → running → completed/failed → judged；失败重试需显式操作。任务版本冲突被拒绝，重放同一 commandId 不重复模型调用。计划修改后需重新确认，运行后保留该计划与运行记录。

人工选择 pass/partial/fail/hold，只有有效完成的运行能判断。通过仅覆盖选中需求及测试范围；研发交付明示剩余未验证范围。旧 PRD 的结果可查看，需求变化后不能直接当作新版通过依据。partial/fail 提供返回需求入口，人工编辑后另建基线和 PRD，不自动覆盖。

## 执行
AI 基于已确认 PRD 与需求生成可编辑计划（目标、成功标准、3–20 个案例）。用户确认计划和真实模型使用后执行。Demo 使用固定 React 控件渲染有限页面/步骤；能力验证逐案记录预期/实际/原文核验与失败；POC 接收新输入并真实执行获批任务。自动检查与人工结论分开，失败、超时、中断必须可见，绝不伪装成成功。

研发交付包含 PRD、需求范围、验收与风险、验证报告、运行记录、Demo/POC配置及使用说明。通过验证且来源仍有效后可导出。不得声称模型自己打分即为真实用户认可。

## 验收
示例 Word 访谈完成导入、分析、人工范围、PRD、三个分支、判断、交付和返回修改。覆盖错误文档、陈旧确认、重复执行、运行异常与页面刷新后的恢复。真实模型成功与自动测试使用的替身分开记录。仅使用虚构验收材料，保留用户已有项目和外观。
